# EMERGE-Humanoid 环境配置

## 1. 当前目标需要安装到什么程度

当前目标是把已完成的 LightNav-0 + SONIC 导航链路接入 EMERGE orchestration。第一阶段需要：

1. EMERGE Main Agent、workspace、ACTION queue 和 Controller。
2. WebSocket、ZMQ、msgpack 等 bridge 依赖。
3. 已有且彼此隔离的 `lightnav-0`、`sonic` 和 SONIC 仿真环境。

第一阶段不需要：

- `pi05_server` 独立环境；
- OpenPI checkpoint/server；
- Cosmos Policy；
- LIBERO 仿真依赖；
- VGGT/SAM3 checkpoint/server；
- ImageMagick helper 环境。

因此，“只做 Clone + 主 EmergePolicy 环境”这个判断是正确的，但 README 中主环境的完整安装命令 `-e ".[libero]" + vggt + sam3 + openpi-client + imagemagick` 是面向 manipulation/LIBERO 的完整配置，不是当前导航 MVP 的最小配置。

## 4. 初始化 workspace 与大模型 provider

这不是 Python 依赖安装的一部分，但真正启动 Main Agent 前必须完成一次。

进入交互 shell：

```bash
conda activate EmergePolicy
cd /home/embodied/EMERGE-Humanoid
```

初始化默认配置与 workspace：

```bash
emerge onboard
```

默认位置：

```text
配置：~/.Emerge/config.json
workspace：~/.Emerge/workspace
```

配置一个可调用多模态模型的 provider。可使用 API key，也可使用仓库支持的 OAuth provider。例如 OpenAI Codex OAuth：

```bash
emerge provider login openai-codex
```

然后在 `~/.Emerge/config.json` 中把 `agents.defaults.model` 设置为实际可用的模型，并建议第一阶段关闭尚未准备好 observation manifest 的 Visual Monitor：

```json
{
  "agents": {
    "defaults": {
      "workspace": "/home/embodied/.Emerge/workspace",
      "model": "openai-codex/<实际可用模型>",
      "provider": "openai_codex"
    }
  },
  "visualMonitor": {
    "enabled": false
  }
}
```

不要直接照抄占位模型名；登录后应根据 provider 实际支持的模型填写。第二阶段由导航 driver 持续写 observation manifest 后，再启用 Visual Monitor。

注意：当前代码的交互入口是 `emerge` 或 `python -m Emerge`，不是 README 中部分位置写的 `python -m Emerge agent`。自动化单次任务使用 `python -m Emerge.cli.headless`。

## 5. 何时需要完整官方主环境

只有准备运行 LIBERO manipulation、Object Location（VGGT+SAM3）或 OpenPI client 时，再执行以下扩展配置。

### 5.1 初始化固定版本 submodules

```bash
cd /home/embodied/EMERGE-Humanoid

git submodule sync --recursive
git submodule update --init --recursive
git submodule status
```

每行前面没有 `-` 才代表对应 submodule 已检出。该步骤会下载多个大型仓库，当前导航阶段可以跳过。

### 5.2 安装 manipulation/LIBERO 依赖

```bash
conda activate EmergePolicy
cd /home/embodied/EMERGE-Humanoid

python -m pip install \
  -e ".[libero]" \
  -e third_party/vggt \
  -e third_party/sam3 \
  -e third_party/openpi/packages/openpi-client

bash third_party/imagemagick_env/install.sh
```

### 5.3 单独的 OpenPI server 环境

这属于后续 GR00T/OpenPI manipulation skill，不属于当前 LightNav+SONIC 接入：

```bash
conda create -n pi05_server python=3.12 -y
conda activate pi05_server
python -m pip install --upgrade pip uv

cd /home/embodied/EMERGE-Humanoid/third_party/openpi
GIT_LFS_SKIP_SMUDGE=1 uv pip install \
  --python "$CONDA_PREFIX/bin/python" \
  -e .
```

## 6. 环境隔离原则

| 进程 | 环境 | 原因 |
|---|---|---|
| EMERGE Main Agent + Controller plugin | `EmergePolicy` | orchestration、ACTION queue、WebSocket/ZMQ client |
| LightNav inference server | `lightnav-0` | vLLM、checkpoint、CUDA 依赖 |
| SONIC deployment | SONIC 自己的 setup/deployment 环境 | TensorRT/ONNX/WBC 依赖 |
| SONIC ProcTHOR MuJoCo | `.venv_sim` / `gear_sonic_sim` | MuJoCo 与仿真依赖 |

不要把 LightNav vLLM 安装进 `EmergePolicy`，也不要把 EMERGE 的 torch 版本覆盖到 `lightnav-0` 或 SONIC 环境。EMERGE driver 只通过 WebSocket 和 ZMQ 与另外三个进程通信。
